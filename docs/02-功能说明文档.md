## 1 系统角色与权限

系统设计两类用户角色，实现管理员（指挥员）与一线执勤人员的分工协作：

| 角色 | 标识 | 能力范围 |
|------|------|----------|
| **管理员/指挥员** | role = 1 | 全局态势监控、事件审核确认/驳回、智能派单调度、统计分析、系统设置 |
| **执勤人员** | role = 2 | 查看分配任务、接受/拒绝派单、上报处理进度、提交反馈、管理在线状态 |

## 2 登录认证

### 2.1 登录页面

- **科技感视觉**：深色渐变背景 + Canvas粒子流动画 + 网格扫描线
- **品牌标识**：系统名「智瞰危局」+ 英文副标题「INTELLIGENT CRISIS OBSERVATORY」
- **输入验证**：用户名(3-20字符) + 密码(6-30字符)
- **登录成功过渡**：卡片缩放消失 → 绿色勾选动画 → 1.5秒后自动跳转
- **记住密码**：本地存储 Token 持久化
- **角色自动路由**：管理员进入 `/dashboard`，执勤人员进入 `/responder/dashboard`
- **多角色活跃会话检测**：登录页自动检测当前浏览器已登录的角色，显示快捷访问按钮，可一键切换至已登录角色的控制台
- **根路径引导**：访问 `/` 时统一跳转至登录页，由用户选择角色入口

### 2.2 认证机制

- JWT Token 认证，有效期 2 小时
- 请求头自动注入 `Authorization: Bearer <token>`
- Token 过期自动清除并跳转登录页（执勤人员端自动携带 `role=responder` 参数，确保重登后回到正确角色入口）
- Admin 端和 Responder 端使用独立秘钥隔离
- **双角色同时登录**：管理员与执勤人员可在同一浏览器同时在线，使用角色前缀隔离的 Token 存储（`admin_access_token` / `responder_access_token`），登录/登出互不干扰
- **本地化用户信息**：用户信息从 localStorage 恢复，登出时仅清理本地状态，无需后端登出接口

## 3 管理员端功能

### 3.1 态势总览（Dashboard）

管理员主控台，一屏呈现全局态势：

#### 3.1.1 顶部状态栏
- **事件总数**：全部聚合事件计数
- **今日新增**：当日新增事件数
- **处理中**：当前活跃事件数
- **在线人员**：当前在线执勤人员数

#### 3.1.2 事件卡片列表（右侧面板）
- 展示聚合后的**事件**（非原始消息）
- 支持按灾种类型筛选（洪涝/火灾/地震/台风/泥石流/其他）
- 支持按事件状态筛选（待审核/已确认/处理中/已完成/已驳回）
- 事件卡片显示：灾种标签、严重程度标记、事件摘要、置信度、位置、时间
- 卡片点击打开事件详情弹窗
- WebSocket 实时推送新增/更新事件，无需手动刷新

#### 3.1.3 事件详情弹窗
- **基本信息**：灾害类型、事件状态、严重程度（轻微/一般/严重/特别严重）
- **位置信息**：文字描述 + 经纬度
- **置信度**：AI 评估的综合可信度百分比
- **事件摘要**：自动生成的事件描述
- **证据链可视化**：从后端 API 实时拉取关联原始消息，以链式卡片形式展示（来源平台标签、发布者、原文内容、位置信息），卡片间连线箭头标识证据时序关联
- **AI 分析结果**：灾种判定、置信等级、AI 建议处置措施（优先展示后端 AI 实时返回的真实建议与关键词）
- **谣言研判分析面板**：
  - **ECharts 5维雷达图**：来源可靠性、内容一致性、逻辑合理性、细节完整度、情绪客观性多维度可视化
  - **谣言判定标签**：✅信息可信（绿色）/ ⚠️待核实（黄色）/ ❌疑似谣言（红色）
  - **置信度进度条**：发光动画显示 AI 评估得分
  - **研判理由**：展示 AI 分析的谣言判定依据
  - **关键词标签云**：AI 提取的核心信息关键词
- **事件时间线**：状态流转时间轴（创建→确认→派单→处理→完成）
- **操作按钮**：
  - 🟢 **确认事件**：将待审核事件标记为已确认
  - 🔴 **驳回事件**：标记为谣言/无关，需填写驳回原因
  - 📋 **派发任务**：打开派单弹窗

#### 3.1.4 派单弹窗
- 自动列出空闲执勤人员
- 可填写任务描述、截止时间、注意事项
- **智能派单**（综合评分算法）：
  - **距离评分（60%权重）**：基于 Haversine 公式计算执勤人员与事发地距离，距离越近分数越高
  - **岗位匹配评分（40%权重）**：首选岗位40分、次选28分、其他匹配岗位16分
  - 支持10类灾种的岗位映射规则（火灾→消防/医疗/警务，洪涝→消防/医疗/志愿者，暴雪→消防/志愿者/医疗 等）
  - 返回匹配人员姓名 + 匹配理由（候选人数、岗位匹配度、距离），前端弹窗确认后派单
- 派单后事件状态自动变为「已派单」，WebSocket 推送通知

#### 3.1.4a 志愿者接单审批
- 管理员仪表盘集成志愿者接单申请面板
- 志愿者主动申请接单后，系统创建「待审批」状态的派单记录
- 管理员可实时查看志愿者姓名、申请事件摘要、灾种类型
- 操作：同意（事件进入处理中）/ 驳回（返回志愿者通知）

#### 3.1.5 执勤人员面板
- 显示在线/总数统计
- 人员列表：姓名、岗位、当前状态
- 状态标识：空闲(绿)、已派单(蓝)、执行中(橙)、离线(灰)

#### 3.1.6 系统状态监控
- CPU/内存/网络使用率可视化
- 数据源状态实时指示
- 数据更新每10秒平滑刷新

### 3.2 事件流监控（Event Stream）

实时呈现多源消息的接入、清洗、AI研判全过程。消息监听已全局化，切换至其他页面后仍持续接收新消息，返回时自动展示最新数据：

#### 3.2.1 消息流面板
- 实时滚动显示新接入的原始消息
- 每条消息展示：来源平台标签、发布者、原始文本、清洗后文本
- **AI研判标注**：
  - 灾害类型标签
  - 信息类型标签（求助/谣言等）
  - 严重程度星级评分
  - 置信度进度条（颜色分级）
- **谣言高亮**：红色背景标记疑似谣言消息，相关增强：
  - **谣言横幅警告**：闪烁☸图标 + “疑似谣言”标签 + “AI研判低可信度信息”提示
  - **脉冲动画**：卡片红色边框缓慢脉冲发光（`@keyframes rumor-pulse`）
  - **谣言标记标签**：尾部危险标签“谣言标记”醒目提示
  - **触发条件**：infoType=谣言 或 confidence<30 均触发谣言展示
- **高置信度高亮**：绿色左侧边框标记可信消息，新增绿色“可信横幅”（✓图标 + “高可信度”标签 + “AI研判可信信息”提示）
- 入场动画：blur模糊渐显 + 滑入效果

#### 3.2.2 实时统计侧边栏
- 消息总数
- 高置信度消息数
- 谣言识别数
- 已驳回事件数

#### 3.2.3 置信度阈值控制
- 可调滑块（0%-100%）
- 超过阈值的消息自动生成事件
- 低于阈值进入「待复核池」

#### 3.2.4 最新事件列表
- 按时间倒序显示最新生成的聚合事件
- 可点击查看事件详情

#### 3.2.5 数据源控制
- 一键开启/暂停模拟数据源
- WebSocket 连接状态实时显示
- **前后端状态同步**：切换前先查询后端实际运行状态，避免前后端状态不一致；出错时自动重新同步
- **数据重置感知**：监听 `DATA_RESET` WebSocket 通知，管理员在设置页清除数据后，事件流页面自动同步——停止接收状态、清空本地事件列表和统计数据，并弹出提示

#### 3.2.6 一键批量智能派单
- 事件流页面顶部新增「一键智能派单」按钮
- 自动对所有已确认待派单事件执行智能派单
- 按严重度降序+时间升序排列优先级
- 返回批量结果（总数/成功数/失败数）

## 5 AI 智能分析功能

### 5.1 灾种识别

利用通义千问大模型对原始文本进行10类灾种分类：

| 灾种 | 说明 |
|------|------|
| 洪涝 | 暴雨、内涝、洪水 |
| 地震 | 震感、建筑倒塌 |
| 台风 | 大风、暴风雨 |
| 火灾 | 着火、爆炸 |
| 泥石流 | 山洪、泥石流 |
| 山体滑坡 | 滑坡、塌方 |
| 干旱 | 缺水、旱灾 |
| 暴雪 | 大雪、冰冻 |
| 雷电 | 雷击、电击 |
| 其他 | 其他类型灾害 |

### 5.2 信息类型分类

7种信息类型自动判定：
- **求助**：被困、需要救援
- **报平安**：确认安全
- **灾情通报**：官方通报
- **物资需求**：需要食品/药品等
- **人员失踪**：失联、走失
- **道路阻断**：交通中断
- **其他**

### 5.3 严重程度评估

4级严重性评估：

| 等级 | 值 | 特征 |
|------|-----|------|
| 轻微 | 0 | 小范围、无人员伤亡 |
| 一般 | 1 | 局部影响、少量损失 |
| 严重 | 2 | 较大影响、有人员伤亡 |
| 特别严重 | 3 | 大范围灾害、重大伤亡 |

### 5.4 置信度评分

5档置信度评估，综合文本可信特征、信息来源、描述细节等维度：

| 档位 | 分值 | 处理方式 |
|------|------|----------|
| 极高置信 | 90-100 | 自动推荐确认 |
| 高置信 | 70-89 | 优先审核 |
| 中置信 | 50-69 | 常规审核 |
| 低置信 | 30-49 | 进入待复核池 |
| 极低置信 | 0-29 | 疑似谣言/无关 |

### 5.5 谣言检测

多维度谣言判定：
- 信息来源可靠性评估
- 内容事实性验证
- 常见谣言模式特征匹配
- 逻辑自洽性检查
- 输出谣言判定、原因说明、处理建议

### 5.6 NLP 向量化聚类

基于 text-embedding-v2 模型的语义级去重聚类：

1. **文本向量化**：将每条消息转为1024维密集向量
2. **余弦相似度计算**：新消息与所有已有事件计算语义相似度
3. **阈值判定**（默认0.75）：
   - 相似度 ≥ 阈值 → 合并至已有事件，追加为证据
   - 相似度 < 阈值 → 创建新聚合事件
4. **事件摘要更新**：多条消息聚合后自动更新事件摘要
5. **证据链维护**：原始消息→事件的映射关系完整保留

### 5.7 智能派单匹配

根据灾种自动匹配合适岗位的空闲人员：

| 灾种 | 优先岗位 |
|------|----------|
| 火灾 | 消防 |
| 地震/泥石流/滑坡 | 消防 + 医疗 |
| 洪涝/台风 | 消防 + 志愿者 |
| 交通事故 | 警务 + 医疗 |
| 其他 | 志愿者 |

## 6 实时通信功能

### 6.1 WebSocket 推送

系统通过 WebSocket 实现全局实时通信，以下事件触发即时推送：

| 触发事件 | 推送内容 | 接收方 |
|----------|----------|--------|
| 新消息入库 | 消息详情 + AI分析结果 | 管理员端 |
| 新事件生成 | 事件摘要 + 灾种 + 严重度 | 管理员端 |
| 事件状态变更 | 事件ID + 新旧状态 | 管理员端 + 执勤人员端 |
| 人员状态变更 | 人员ID + 新旧状态 | 管理员端 |
| 任务状态变更 | 任务ID + 新旧状态 | 管理员端 + 执勤人员端 |
| 高危告警 | 严重事件完整信息 | 管理员端 |
| 系统通知 | 通知文本 | 全端 |

### 6.2 连接管理

- **自动重连**：断线后3秒间隔重连，最多5次
- **心跳机制**：30秒间隔 PING/PONG
- **JWT 认证**：连接时 URL 携带 Token
- **消息队列**：断线期间消息缓存，重连后补发
